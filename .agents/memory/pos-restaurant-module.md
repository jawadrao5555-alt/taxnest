# Restaurant module (NestPOS) — full invariants

## Gating
Restaurant = Pro/Unlimited + active TRIAL. `PosFeatureService::forCompany()` masks restaurant-category flags OFF unless the active plan's `restaurant_enabled` COLUMN is 1 (never plan IDs) OR the subscription is an active non-expired trial (mask returns on expiry). Nav "Tables"/"Kitchen Display" links gate on effective flags (forCompany), not `restaurant_mode`. `pricing_plans.features` JSON is DISPLAY-ONLY marketing copy; plan cards render limits from the limit columns + cumulative "Everything in <prev>, plus:" lists. Stored flags preserved — locked saves don't wipe config; upgrade restores. Features page greys out with "Pro/Unlimited only" label.

## Dine-In table picker (F3)
Universal screen order-type 'Dine In' + tables ON → Alpine floor/table modal; select reserves (occupied), auto-frees on final payment AND cancel/delete. T/D/N gated OFF while open. Opens from BOTH the Dine In pill AND the guided keyboard type step (confirmGuidedType routes through setOrderType); full keyboard state (arrows/Enter/Esc), selectTable resumes the guided chain; clearCart resets orderType to takeaway.
- **Dine-In Auto KOT (owner, Jul 2026)**: `companies.dine_in_auto_kot` (default OFF, Kitchen Settings toggle, admin-only; updateKitchenSettings write is hasColumn-guarded for prod self-heal). ON → selectTable auto-runs `holdOrder({forcePrintKot:true})` when cart non-empty AND NOT editing/incoming-order/manual/deal items → KOT fires + bill lands in Recall; on hold failure it falls through to the normal guided-chain resume (cart kept, manual F5 possible). Owner flow: Name → Products → Dine In → Table = LAST step. Waiter side needs NO code — storeOrder already stamps kot_sent_at + sends to cashier. Don't confuse with `auto_print_kot` (print-after-sale, different column).

## Counter/Station KOT routing
`pos_stations` — counters claim product categories (case-insensitive; one ACTIVE counter per category + unique names, validated). `PosStation::prepareTicket` is the SINGLE resolver for BOTH KOT render paths (kitchen-ticket route + Agent print job) — never let them diverge. Unassigned categories/manual items/services → default KITCHEN (id 0). Zero stations = ONE FLAT list, NO category sections (ZFC feedback 21 Jul 2026 — reversed white-on-black category headers printed blurry on cheap thermal + kitchen doesn't want them; grouped = single 'ALL' key, blade hides header when count==1; do NOT re-add category grouping). Station headers (real stations) now black-on-white bold (never reversed blocks on thermal). Silent print with stations & no station_id: server splits one job per counter-with-items (counter printer ?? kot_printer; ANY bucket missing printer → 409 whole request → client falls back to full popup). Empty station ticket never prints (blade guard signals/closes; agent 204). KDS counter picker (localStorage `kds_station`, `?station=` override, whitelist) filters cards/aggregate/counts/auto-print; pinned KDS delta fires per-station via `unprinted_by_station` (order-wide count would print blanks on other counters). Station CRUD on Kitchen Settings, admin-only; printer must be agent-known (loud error, not silent null).

## Kitchen account + KDS (F4/F5)
`pos_kitchen` login → confined to /pos/restaurant/kds. KDS uses separate `kitchen_status`+timestamps (NEVER touches restaurant_orders.status — that drives tables); scan (scanner/camera) or manual button clears; KOT carries CODE128 barcode ONLY (QR REMOVED per owner Jul 2026 — do NOT re-add; html5-qrcode camera reads 1D CODE128 fine, scan-to-clear intact). KDS "Clear All" button (Jul 2026): bulk endpoint takes EXPLICIT ids of the board's visible (station-filtered) orders — a station-pinned display must never clear other counters; company-scoped, race-safe (whereNull kitchen_cleared_at), kitchen-side only so held bills survive. `pos_kds_auto_print` (admin-only POST) → KDS auto-prints NEW orders once (localStorage seed, no dupes) AND delta tickets for appended items ({id,delta} queue, 30s throttle); per-card manual reprint works with auto-print OFF (`kot_reprint_enabled`).
- **Cashier-side KOT suppression + pay-time delta (owner, Jul 2026)**: universal screen `kdsHandlesKot()` (= kds_enabled && pos_kds_auto_print, exposed via $kitchenSettings.kds_auto_print) suppresses ALL cashier-side AUTO KOT fires — holdOrder auto block (print_on_hold/forcePrintKot incl. dine_in_auto_kot + Send-to-Kitchen) AND runAutoPrintChain wantsKot — because the KDS station prints the same ticket (duplicate). Explicit reprints stay UNGATED: resendKitchen, receipt-popup KOT button, K-key reprint. AND: auto-chain `kotDelta` is now ALWAYS true (was recall-only) — pay-time auto-KOT prints ONLY kot_printed_at-NULL rows; fresh pass-through orders (no stamps) still print full; fully-printed waiter/held bills print NOTHING at settle (empty ticket = blade guard closes / silent endpoint success with 0 jobs — chain never stalls). Cancelled hold-time print dialog loses its pay-time reprint safety net (stamp happens at render) — manual reprint covers it, accepted. PLUS: **dine-in finals NEVER auto-KOT** (owner, Jul 2026) — runAutoPrintChain takes orderType (captured in payHeldOrderDirect from the heldOrders entry BEFORE the success-filter removes it; pass-through falls back to the widget) and gates wantsKot on `orderType !== 'dine_in'`; takeaway/delivery counter sales keep Auto-KOT (kitchen cooks after pay there).

## Waiter tablets (F6)
`pos_waiter` login → confined to /pos/waiter (customer, table reserve, product grid, send to chosen cashier, append to own held orders). Orders = RestaurantOrder rows (status 'held', source='waiter', assigned_cashier_id) — KDS/tables/day-close see them with zero new lifecycle. Cashier pickup = **Table-se-Bill (owner-approved, Jul 2026 — REPLACED both the top "Waiter" button and the auto-load)**: waiter order lands as a toast hint + teal count badge on the Table button; cashier opens the F3 table picker (openTablePicker refreshes tables AND incoming) — table with a waiting order renders as a PURPLE clickable "Order Tayyar" card (selectTable claim branch = early return at TOP, before the occupied guard); tableless takeaway/delivery waiter orders sit in a "Counter Orders (bina table)" section of the same picker. Click → `claimAndLoadIncoming` (client `_claimBusy` guard) → POST claim → cart builds from the **FRESH `order` in the claim response** (waiter may append between poll and claim — never build from the stale polled object); 409 → toast + refresh both lists. `loadIncomingToCart` MUST carry `o.order_type` onto the cart (bill's order_type snapshot drives the DINE-IN/TAKE AWAY receipt badge; default-takeaway bug caught in e2e). The old Incoming drawer + F6 stay as a HIDDEN fallback (KOT reprint) and its Load-to-Cart ALSO routes through claimAndLoadIncoming. **Claim = server-side ATOMIC single-winner** (conditional UPDATE setting assigned_cashier_id while still held+unassigned/mine; MySQL affected-rows=0 on same-value needs an already-mine re-check; `isPosAdmin()` bypasses the assigned check so admins can rescue orders stuck on an off-shift cashier). **Why:** payment runs BEFORE settlement's claim — two terminals loading the same unassigned order would both charge/report a final bill and only one settles. Any future pickup path MUST claim first. FINAL bills only settle the waiter order — provisional save leaves it in Incoming; settle via manual storeInvoice path (quota charged THERE only; waiter sends free) → `/pos/api/incoming-orders/{id}/complete` links txn + frees table. Known limitation (accepted): waiter appends AFTER claim don't reach the already-loaded cart. Delta-KOT: `restaurant_order_items.kot_printed_at` — only NULL rows print, so appends print alone. Once-per-day cashier (owner Jul 2026): waiter picks a cashier ONCE per LOCAL day — localStorage key per waiter id (`waiter_day_cashier_{id}`, {date,id}), restored only if id still in server-rendered active-cashier list; send() intentionally never resets cashierId. No DB column — deliberate (per-tablet convenience, not policy). **Sales by Waiter report**: buildReportRangeAnalytics `waiters` = RestaurantOrder source='waiter'+status='completed'+whereIn(pos_transaction_id, filtered txn $ids) — inherits tab/cashier/date filters via $ids; revenue/tax from linked txns; day-close-washed bills drop out automatically (FK set-null); rendered on /pos/reports + analytics PDF only when non-empty.

## Deals — day-based combos
`pos_deals` (price, active_days JSON ISO 1–7 empty=daily, optional starts_on/ends_on) + `pos_deal_items` (component pos_products, no FK per shared-table rule); admin CRUD at /pos/deals. Universal sale screen only: server-side `isActiveOn()` filter → `$dealsForJs`, Deals pill, never in localStorage cache. Server ENFORCES deal price (client price ignored) + freezes `pos_transaction_items.deal_snapshot` [{product_id,name,qty}]; ALL stock paths expand from SNAPSHOT (never live deal items) via `expandDealComponentsForStock()`. Billing-only: `hasDealItems()` blocks Hold/KOT + routes pay to processPaymentManual (restaurant hold 422s on 'deal'). No re-check of isActiveOn at storeInvoice (midnight-crossing cart honored). Receipts/PDF/show render snapshot components as indented no-price sub-lines.

## Public QR profile + menu (F8)
`companies.public_profile_slug` (random 24 lowercase, unique, regenerable — old QRs die) + `public_profile_settings` JSON (enabled + per-detail show/hide + hours/about) + `pos_menu_items` (company_id+pos_product_id unique, sort; NO price copy — public page reads LIVE from pos_products, company-scoped + is_active only; no FK per shared-table rule). Public GET /menu/{slug}: throttle:60,1, slug regex, disabled/unknown = same as unknown route (no enumeration), noindex; website renders as link ONLY when ^https?:// (else plain text). Admin section on POS Business Profile page (cashiers: middleware-blocked + controller 403). Receipts 80mm/58mm: ONLY local/provisional @else branch — QR switches from JSON blob to public URL when enabled; PRA fiscal + offline branches untouched.

## Order-type flow rules (owner, Jul 2026)
- Gate (`typeFlowGate`) = ANY of tables/kot/kitchen/delivery effective flags ON (PosFeatureService::forCompany) — i.e. exactly when the order-type widget is visible. Plain retail (all four OFF) is completely ungated.
- Rules when gated: **Delivery** = final OR provisional, no Hold/KOT. **Dine-In** = ONLY Hold/KOT/recall, provisional blocked. **Takeaway** = direct final bill only (both blocked).
- **KOT delta on recall (owner, Jul 2026)**: recall+re-hold RECREATES the restaurant order (old cancelled, items deleted) — holdOrder MUST carry `kot_printed_at`+`kot_batch_no` forward for unchanged lines (pool keyed type|id|lower(name)|int(qty)|trim(notes), consumed one-per-match) or the next ticket re-fires every dish. Client: updated orders print `&delta=1` (holdOrder captures wasRecall BEFORE clearCart; runAutoPrintChain captures `!!recalledOrderId` at invocation). Manual K-key/KOT button/resend reprints stay FULL. Qty-changed lines intentionally reprint as new (no pool match). KDS delta auto-fixed by the preserved stamps.
- Enforced in FOUR places: universal.blade.php `canHold()`/`canProvisional()` (guards inside holdOrder/saveProvisionalDirect cover F5/F9/P keys; buttons :disabled with tooltip — DISABLE, not hide), PosController::storeInvoice (provisional 422 unless delivery — gate SKIPPED when order_type absent so legacy offline replays/plain retail payloads pass), RestaurantPosController::holdOrder (422 unless dine_in), RestaurantPosController::payOrder (provisional 422 unless held order's type = delivery).
- **billing_flow TRAP**: the universal screen's NORMAL payment pipeline routes plain-product restaurant sales through hold-then-pay (processPayment → orders/hold → payOrder) for KOT/restaurant_orders bookkeeping. A naive dine_in-only hold gate breaks EVERY final Takeaway/Delivery sale. The internal pass-through sends `billing_flow: true` and holdOrder exempts it (workflow rule, not security — payOrder still owns the delivery-only provisional gate; explicit Hold button/F5 sends no flag and stays blocked).
- FBR universal port intentionally NOT gated (PRA-only feature set).

## Table occupied timer + Kitchen Efficiency (owner, Jul 2026)
- `restaurant_tables.occupied_since` (datetime cast) — stamped when a table flips to 'occupied' (holdOrder + waiter order), PRESERVED on append/recall to an already-occupied table (holdOrder reads the pre-fetched $table and keeps the original timestamp), NULLed on EVERY free path (holdOrder oldOrder-cancel, deleteOrder, payOrder, waiter settle, releaseTable, storeInvoice reserved-free, CleanZombieTables). Reserved (amber) elapsed reuses locked_at. Any NEW free path must also null occupied_since.
- Display: universal picker tiles + held-orders modal (`elapsedSince(ts)` helper reading `nowTick`, 30s interval — restaurant mode only), /pos/restaurant/tables (server diffForHumans), FBR port picker (server-rendered). table-status API returns occupied_since (UTC ISO).
- Kitchen Efficiency card = restaurant dashboard WRAPPER (dashboard.blade.php after the style @include, style-independent). Avg prep = kot_sent→kitchen_ready, clear = ready→cleared; computed in PHP from last-7-day kot_sent rows (Carbon 3: diffInMinutes MUST pass absolute=true). All "—" until KDS statuses actually used; deleting an order deletes its timing rows.
- **KDS card timer starts at KOT time (owner, Jul 2026)**: elapsed + H:i display use `kot_sent_at ?: created_at` in BOTH payload builders — RestaurantKdsController::liveOrders AND the kds.blade.php initial @php JSON (keep in sync!). Blade diff direction = `$kdsStart->diffInMinutes(now())` (Carbon 3 signed — reversed order goes negative). Hold/resend/waiter-append all refresh kot_sent_at → timer restarts on any new ticket (accepted/intended).
- KDS clearing needs NO kitchen account — any admin/cashier opens /pos/restaurant/kds from nav; pos_kitchen role is confined TO kds, not the only one with access.
