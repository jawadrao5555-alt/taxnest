IMPLEMENT SUBSCRIPTION OVERRIDE + USAGE LIMIT SYSTEM (FINAL)

GOAL:
Support full admin control:

* Lifetime free companies
* Temporary free access
* Grace period
* Invoice-based free limit (e.g. 10,000 invoices)

════════════════════════════════════
STEP 1 — DATABASE
════════════════════════════════════

Create migration:

Add to subscriptions table:

* override_type ENUM(‘none’,‘grace’,‘temporary’,‘lifetime’,‘usage_free’) DEFAULT ‘none’
* override_until DATETIME NULL
* free_invoice_limit INT NULL
* override_reason VARCHAR(255) NULL
* override_by BIGINT NULL

Run migration safely (nullable only, no destructive change)

════════════════════════════════════
STEP 2 — CORE LOGIC
════════════════════════════════════

Create helper:

function hasAccess($company)

Logic order:

1. IF override_type = lifetime → allow
2. IF override_type = usage_free:
    allow IF invoice_count < free_invoice_limit
3. IF override_type = temporary OR grace:
    allow IF now < override_until
4. ELSE:
    normal subscription check (is_active + expires_at)

════════════════════════════════════
STEP 3 — ENFORCEMENT
════════════════════════════════════

Where plan.limit middleware is used:

* BEFORE checking limits
* CALL hasAccess()

IF access = false:
→ block request (403)
→ message: “Your plan has expired. Contact admin.”

For usage_free:
→ block when invoice limit reached

════════════════════════════════════
STEP 4 — ADMIN CONTROL
════════════════════════════════════

In Admin panel (company management):

Add actions:

1. Grant Lifetime Access
2. Grant Temporary Access (date picker)
3. Grant Grace Period (7 / 15 days quick)
4. Grant Free Invoice Limit (input number e.g. 10000)
5. Remove Override

Each action must:

* save override_type
* save override_until (if needed)
* save free_invoice_limit (if usage_free)
* save override_reason
* save override_by (admin id)

════════════════════════════════════
STEP 5 — RULES
════════════════════════════════════

* Only ONE override active at a time
* Override ALWAYS overrides subscription
* DO NOT modify expires_at
* DO NOT delete subscription data

════════════════════════════════════
STEP 6 — SAFETY
════════════════════════════════════

* All fields nullable
* No impact on existing companies
* Existing subscriptions remain intact
