PHASE 3 — LOGIN ISOLATION (ADMIN-UNIFIED + COMPANY-STRICT)

GOAL:
Keep ADMIN unified login (any panel), but block cross-login for company users.

-------------------------------------

A) CURRENT PROBLEM

- DI login pe POS/FBR credentials → redirect + fail
- POS login pe DI credentials → redirect + fail

This causes confusion + security leak.

-------------------------------------

B) FINAL RULESET

1) ADMIN (SUPER USER)

- Can login from ANY login page:
  /login
  /pos/login
  /fbr-pos/login

- On success:
  → ALWAYS redirect to /admin/dashboard

-------------------------------------

2) COMPANY USERS (STRICT ISOLATION)

Guard mapping:

/login        → web (DI)
/pos/login    → pos (PRA POS)
/fbr-pos/login→ fbrpos (FBR POS)

RULE:

- If credentials belong to another guard:
  → DO NOT redirect
  → DO NOT auto-detect
  → return:

    "Invalid credentials"

-------------------------------------

C) IMPLEMENTATION LOGIC

In each login controller:

STEP 1 — Attempt ADMIN login first (global check)
(if admin table / guard exists)

if (Admin::where(...credentials...)->exists()) {
    Auth::guard('admin')->login($admin);
    return redirect('/admin/dashboard');
}

STEP 2 — Attempt CURRENT GUARD ONLY

if (Auth::guard('<current_guard>')->attempt($credentials)) {
    return redirect()->intended(...);
}

STEP 3 — FAIL

return back()->withErrors([
    'login' => 'Invalid credentials'
]);

-------------------------------------

D) IMPORTANT

REMOVE any logic that:

- detects user across multiple guards
- redirects based on "user type"
- checks product_type before auth

-------------------------------------

E) SECURITY BENEFIT

- No information leak (user type hidden)
- No accidental cross-panel login
- Clean UX

-------------------------------------

F) AUTOMATED TESTS

1. Admin credentials on /pos/login
   → PASS → /admin/dashboard

2. Admin credentials on /login
   → PASS → /admin/dashboard

3. POS user on /login
   → FAIL → "Invalid credentials"

4. FBR user on /pos/login
   → FAIL → "Invalid credentials"

5. DI user on /fbr-pos/login
   → FAIL → "Invalid credentials"

6. Correct login on each panel
   → PASS

-------------------------------------

ASSERTIONS

- No redirect to wrong panel
- No mixed guard sessions
- Admin always universal
- Company users always isolated

-------------------------------------

OUTPUT REQUIRED

- Files changed
- Before vs after behavior
- PASS/FAIL tests
- FINAL VERDICT: SAFE / NOT SAFE
