CRITICAL RULES:

=====================================
STEP 0 — FEATURE FLAGS (MANDATORY)
=====================================

Add to company settings / config:

- enable_fbr_retry_system (default: false)
- enable_hs_mapping_manager (default: false)
- enable_reduced_rate_mapping (default: false)

All new logic must check flags BEFORE execution.

=====================================
STEP 1 — FAILED INVOICE RECOVERY
=====================================

Backend:

- Add nullable columns (SAFE):
  - retry_count (int, default 0)
  - last_retry_at (timestamp nullable)

- Create Job:
  RetryFailedFbrInvoicesJob
    - fetch invoices where fbr_status = 'failed'
    - retry max 3 times
    - delay = 5 minutes
    - skip if retry_count >= 3

- Add endpoint:
  POST /admin/fbr/retry/{invoice}

Frontend (simple table, no heavy UI yet):

- List failed invoices
- Show:
  - invoice_id
  - error message
  - retry_count
- Button: Retry

=====================================
STEP 2 — HS CODE MAPPING MANAGER
=====================================

Backend:

- Use existing hs_code_mappings (GLOBAL)

- Add endpoints:
  GET /admin/hs-mappings
  POST /admin/hs-mappings
  PUT /admin/hs-mappings/{id}

Frontend:

- Simple CRUD table:
  - HS code
  - sale_type
  - SRO
  - serial

Validation:

- If invoice item HS not found in mapping:
  → log warning (DO NOT BLOCK)

=====================================
STEP 3 — REDUCED RATE SUPPORT

NO removal of fallback yet (safety)
