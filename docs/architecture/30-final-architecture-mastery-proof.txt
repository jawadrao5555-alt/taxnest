A) NESTPOS / PRA
~~~~~~~~~~~~~~~~

Call chain (FACT citations):

1. USER ACTION: NestPOS sale screen posts to POST /pos/invoice/store
2. ROUTE: routes/web.php ~857 middleware ['pos.auth','company.approval'] prefix pos;
   ~953 Route::post('/invoice/store', PosController@storeInvoice)
   + plan.limit:invoices
3. GUARD/MIDDLEWARE: PosAuth
   - Auth::guard('pos')
   - product_type must be pos
   - app()->instance('currentCompanyId', $user->company_id)
   - BranchContextService::getActiveBranchId → currentBranchId
   - Role confinement for kitchen/waiter/rider/viewers (cashiers not blocked from store)
4. CONTROLLER: PosController::storeInvoice (~3063)
   - companyId = app('currentCompanyId')
   - validates items/payment/discount/offline_uuid
5. TAX:
   - PosTaxRule::getRateForMethod
   - company->posTaxPricingMode()
   - inclusive → PosTaxMath::inclusiveHeader (total_amount whole-rupee)
   - exclusive → round tax and total to whole rupee (PosController ~3305-3309)
6. REPORTING STATE:
   - provisional: invoice_mode=local, pra_status=local
   - reporting ON final: invoice_mode=pra, pra_status=pending
   - reporting OFF final: invoice_mode=pra, pra_status=NULL
     PROOF: must NOT be 'local' (PosController ~3426-3445)
7. PERSISTENCE: pos_transactions (+ items/payments), company_id stamped;
   offline_uuid unique (company_id, offline_uuid)
8. PRA:
   - if praEnabled and company->agentHandlesPra(): leave pending; skip server submit
   - else PraIntegrationService::sendInvoice
   - Company::agentHandlesPra: pra_connection_mode === fiscal_device → ALWAYS true
   - PraIntegrationService::sendInvoice early-return for fiscal_device BEFORE curl/PraLog
     (~324-335) — defense in depth
9. PRA LOGS: PraLog created on cloud path only
10. PRINT (separate request): POST /pos/api/print-jobs → apiCreatePrintJob
    - target_printer and device_uid stamped at create (SNAPSHOT of routing decision)
    - PosPrintJob::created → afterCommit → PrintJobWakePublisher
11. AGENT: long-poll claim /api/agent/print-jobs + content + result
12. DAY CLOSE: GET/POST /pos/day-close; AutoCloseDayPos via pos:auto-dayclose hourly

Proofs required by mission:
- Whole-rupee: exclusive round in storeInvoice; inclusive totals in PosTaxMath
- Reporting-OFF final: pra_status NULL + invoice_mode pra (not local)
- fiscal_device: agentHandlesPra + sendInvoice early-return — server must not direct-submit
- Idempotency: offline_uuid replay returns same success; unique index
- Printer target: stamped on pos_print_jobs at enqueue (SoT for that job);
  note: AgentController has stranded-job rescue that may rewrite target_printer later
- Tenant isolation: currentCompanyId on all writes; product_type gate
- Branch isolation: stampBranchId / branch filters; BranchContextService

5. SUPER ADMIN / IMPERSONATION / COMPANY CONTEXT PROOF
------------------------------------------------------

Entry UI: resources/views/saas-admin/companies/show.blade.php
- "View as Company" → POST impersonate (mode not full → view)
- "Manage as Company" → POST impersonate mode=full

Route: POST /admin/companies/{id}/impersonate
Controller: AdminCompanyController::impersonate
Gate: assertSuperAdmin() — AdminUser::isSuperAdmin only

Target selection:
- Company must company_status=active
- Guard mapped from product_type / NestErps vertical (pos/fbrpos/health/web)
- User: first active company_admin; POS fallback pos_admin

Session behavior:
- auth($panelGuard)->login($companyAdminUser)
- admin guard LEFT LOGGED IN (dual-guard coexistence)
- session()->regenerate()
- session key 'impersonation': admin_id, company_id, company_name, guard, mode, readonly

View vs Manage — ONE system, two modes:
- mode=view → readonly=true → ReadOnlyImpersonation blocks non-GET writes
- mode=full → readonly=false → writes allowed; LogImpersonatedWrites audits
  AdminAuditLog action "Full-access change while impersonating"
- Both modes block identity swaps (login/logout/demo-login)
- /admin/* always allowed so Exit/Lock remain reachable

Lock: POST /admin/impersonation/lock → mode=view, readonly=true (tighten only)
Exit: POST /admin/impersonation/stop → logout PANEL guard only; forget impersonation;
      NEVER session()->invalidate() (would destroy admin)

Orphaned flag: if impersonation set but admin session gone → logout panel user,
forget flag (ImpersonationLoginLockoutTest covers this)

Branch context under impersonation:
- Panel user is that company's admin → PosAuth/FbrPosAuth/HealthAuth bind
  currentCompanyId from that user; BranchContextService uses owner-capable access

Live Ops integration with this architecture (PROOF it does NOT invent parallel systems):
- AdminLiveOpsController::gate → isSuperAdmin only (same AdminUser world)
- Company selection = search/status like /admin/companies (NestPOS product_types scope)
- No staff Live Ops switcher; managers on pos/web redirect to /admin/login
- Tests LiveOpsAuthorizationTest A–F prove boundaries
