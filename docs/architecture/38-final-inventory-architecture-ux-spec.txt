3. ONE-SHEET MASTER EXCEL — EXACT FORMAT (chosen)
================================================================

Compared formats
  A. Keep today’s TWO files (product Excel + recipe Excel)
  B. Recipe-shaped sheet only (BOM lines; infer products)
  C. Row Type sheet PRODUCT | INGREDIENT | RECIPE

[SPEC] Format C. Exactly ONE sheet. Row Type required:
PRODUCT | INGREDIENT | RECIPE. No stock quantity columns.

Sheet name: Master
File: nestpos_inventory_master.xlsx
Never CSV as the default (Pizza Master 8.9E+12 —
PosController::downloadProductTemplate comments).
SKU / Product Code / Ingredient Code columns: Excel TEXT
  (NumberFormat FORMAT_TEXT + setCellValueExplicit string).

Header row 1 (exact titles; importer must also accept aliases)

  A  Row Type
  B  Product Name
  C  Product Code
  D  Price
  E  Category
  F  Description
  G  Tax Rate %
  H  Unit (UOM)
  I  Tax Exempt
  J  Third Schedule
  K  Ingredient Name
  L  Ingredient Code
  M  Ingredient Unit
  N  Cost per Unit
  O  Min Stock
  P  Quantity Needed
  Q  Active

Row Type (required): PRODUCT | INGREDIENT | RECIPE
  (case-insensitive)

Which columns apply
  PRODUCT:    B–J, Q     required: Row Type, Product Name, Price
  INGREDIENT: K–O, Q     required: Row Type, Ingredient Name,
                         Ingredient Unit
                         (N Cost per Unit lives HERE only)
  RECIPE:     B, C, K, L, M, P, Q
              required: Row Type, Product Name or Product Code,
                        Ingredient Name, Quantity Needed
              Quantity Needed = per 1 sold unit
              RECIPE must NOT write cost_per_unit
              RECIPE may create a missing ingredient at cost 0
              IFF no match AND the INGREDIENT pass did not already
              create it (see processing order below)

Forbidden on this sheet
  Qty on hand, opening stock, received qty, supplier, PO/PUR number,
  branch, rate-as-purchase, receipt printer flags, stock-check counts.

---------------------------------------------------------------------------
3.A  MASTER IMPORT PROCESSING ORDER  [SPEC — required]
---------------------------------------------------------------------------

  Pass 1: all INGREDIENT rows
  Pass 2: all PRODUCT rows
  Pass 3: all RECIPE rows

  Empty / Misal: rows are skipped in every pass.

  Why: if RECIPE ran first it would auto-create Rice at cost 0,
  then the INGREDIENT row would fight it. Ingredient-first lets
  cost / code / min stock land before BOM lines attach.

---------------------------------------------------------------------------
3.B  INGREDIENT UNIT-CHANGE RULE  [SPEC — required]
---------------------------------------------------------------------------

  On INGREDIENT match (existing row):
    If the file’s Ingredient Unit differs from ingredients.unit
    AND (the ingredient is used in any product_recipes row
         OR ingredients.current_stock is not 0
         OR any ingredient_stocks.quantity is not 0):
      treat the row as INVALID
      do not change the unit
      do not post any other field from that row
      tell the owner to correct the file to the existing unit

  conversion_factor is unused in RecipeInventoryService.
  [VERIFIED] no conversion_factor reads in that class.
  Silently changing kg → g would make quantity_needed 0.25 mean
  0.25 g instead of 0.25 kg.

  New ingredients (no match): unit is taken from the file and must
  be in RecipeInventoryService::UNITS
  (kg, g, ltr, ml, pcs, dozen, pack).

Matching (reuse existing precedence)
  Product: barcode → SKU → name
    PosController::importProducts
    IngredientController::importRecipes (code then name)
  Ingredient: Ingredient Code (exact, company, case-insensitive)
              else name|unit exact (PosRecipeExcelImportTest
              test_existing_ingredient_reused_by_name_and_unit)
  Recipe: unique (product_id, ingredient_id) upsert quantity_needed
    ProductRecipe unique index

Sample rows: prefix Product Name or Ingredient Name with “Misal:”
  [VERIFIED] RECIPE_SAMPLE_MARKER in IngredientController

Caps
  Product creates: same 5000 data-row family as importProducts
  Recipe lines: RECIPE_IMPORT_MAX_ROWS = 2000 today; raise only with
  a test, do not silently mix caps.

Gates
  PRODUCT rows: excel_enabled (PosController::planGate)
  INGREDIENT / RECIPE rows: feature:recipes
  A file that also contains PRODUCT rows while recipes is off:
    import PRODUCT rows; skip INGREDIENT/RECIPE with a reason
    (same spirit as Stock-In mixed-file gates — do not refuse
    a valid product-only path).

Idempotency of MASTER re-upload
  PRODUCT match → update catalog fields, never add stock
  INGREDIENT match → update name/code/cost/min/active
                    never change unit if §3.B fires
                    never call adjustIngredientStock
  RECIPE match → update quantity_needed (+ recipe_version increment
                 as importRecipes already does)

6. MATCHING HIERARCHY
================================================================

[VERIFIED] What identity actually exists
  ingredients.code nullable, app-level duplicate check, NO unique index
    IngredientController::store / update
  ingredients.name + unit  (recipe import key)
  No ingredient barcode
  No supplier_item table
  pos_products.sku / barcode / name
    PosController::importProducts

[CHALLENGE] Audit 37 v1 “on first clearance, write supplier code
into empty ingredients.code”. Rejected as default (owner decision 2).

[SPEC] Stock-In match order (company-scoped)

  INGREDIENT lines  (skipped with reason if recipes off)
    1. NestPOS Code exact, case-insensitive, unique-in-company
       If 0 hits → try 2. If 2+ hits → AMBIGUOUS (no unique DB index)
    2. Exact name + unit (strtolower trim), same as
       importRecipes $ingByNameUnit
       Unit on the file MUST equal ingredients.unit
       (no kg↔g; RecipeInventoryService ignores conversion_factor)
    3. Stop. Never name-only. Never fuzzy.

  ITEM lines  (skipped with reason if inventory off)
    1. NestPOS Code against barcode then SKU
    2. Exact name
    3. Stop. No fuzzy.
    Unit compared to pos_products.uom, not kitchen UNITS.

  Supplier Item Code is NOT primary identity in v1.
  Optional: tick “Save as Ingredient Code” only if ingredients.code
  is empty AND the uniqueness check used by IngredientController
  passes. Default OFF (owner decision 2).

Confidence
  step 1 unique hit = MATCHED (auto-tick, still listed)
  step 2 unique hit = MATCHED
  2+ hits / unit mismatch / zero hits = NEEDS CLEARANCE or INVALID

    branch_id          (null only when company has no branches)

    supplier_item_code
    supplier_item_name
    nestpos_code_raw
    qty, unit, rate
    branch_id override nullable
    reference override nullable
    match_status       MATCHED | NEEDS_CLEARANCE | INVALID | SKIPPED_GATE
    matched_ingredient_id nullable
    matched_product_id nullable
    invalid_reason nullable
    selected           bool (checked for post)
    collapsed_into_line_id nullable  (if summed into another line)
    posted_at nullable
    movement_id nullable

Must support
  - stored uploaded workbook identity (filename + parse result)
  - matched / unmatched / invalid / skipped-gate status
  - selected-row posting (Post checked MATCHED lines only;

  - Refresh / Re-match after the owner creates an ingredient on

  - no duplicate stock posting: §12 key after SUM
  - logout/refresh: reopen /pos/inventory/stock-in/{batch}
    (name at implementation) and continue

Post button
  Enabled when at least one SELECTED line is MATCHED and unposted.
  Does not require the entire file to be matched.
  INVALID rows are never selected for post.

10. BRANCH HANDLING
================================================================

[VERIFIED]
  Ingredient master: company-wide (ingredients.company_id)
  Qty: ingredient_stocks unique (company_id, ingredient_id, branch_id)
  Finished goods: inventory_stocks unique (company_id, product_id, branch_id)
  BranchStockService::writeBranchId
    no branches → null
    else preferred, else session, else head office
  Ingredient Adjust modal posts NO branch_id
    → silent session/head office
    RecipeInventoryService::adjustIngredientStock
  healLegacyRows adopts NULL inventory_stocks onto head office
    DOES NOT touch ingredient_stocks
  changeIngredientBranchStock skips when branch_id is null
  First insert can seed quantity with company current_stock
    RecipeInventoryService::changeIngredientBranchStock
    ($initialQuantity often = company before qty)

[SPEC] / [OWNER decision 4]
  Explicit branch selection is REQUIRED for multi-branch Stock-In.
  Never silently use null or all-branches for a multi-branch company.

12.A  SUM THEN IDEMPOTENCY  [OWNER decision 8 / SPEC]
---------------------------------------------------------------------------

  Inside one staging batch, before Post:

    Group unposted SELECTED MATCHED lines by
      line_type + matched_id (ingredient_id or product_id)
      + branch_id + reference_number

    If a group has more than one source row:
      qty  = SUM(qty)
      rate = qty-weighted average of rates that are present,
             else the sole present rate, else 0
      keep all source_row_nos on the snapshot
      mark extras collapsed_into_line_id
      post ONCE for the group

    Example: INV-88 Gulberg Rice 500 kg + Rice 200 kg → one post
    of +700 kg. Do not drop the 200 kg line.

  After collapse, the unique posted key is:

    company_id
    + reference_type 'stock_in'
    + reference_number
    + ingredient_id OR product_id
    + branch_id (or the null-branch token for single-shop)

  Second Post of the same key (same batch retry or a new batch
  with the same Reference for that item+branch): skip, report
  “already received”. No second qty write.

  Failed Post (transaction rollback): posted_at stays null; retry
  safe.

  Same file, new Reference: treated as a new delivery.
