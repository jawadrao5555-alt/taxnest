# Test-only CLI opcode cache

The full PHPUnit command still executes all tests and assertions with a 1GiB PHP heap. `scripts/rc-phpunit-opcache` adds a separately disclosed fixed 128MiB official PHP opcode cache, with JIT disabled. It does not edit production PHP configuration or application route loading. Missing extension or failed runtime canary fails closed; there is no fallback that omits tests.

Use only on a committed immutable checkout, inside `scripts/rc-safe-run`. The wrapper verifies HEAD and the content digest of every tracked file before/after the suite. Timestamp validation stays enabled with immediate revalidation. Generated storage, bootstrap cache, local runtime, public output and temporary files are explicitly uncached. The mandatory same-process canary verifies 10,000 repeated cached closure imports, a changed cached-source timestamp, and generated PHP overwritten at the SAME timestamp. Content-free final metrics report heap peak and the separate opcode cache allocation/use.

A source audit of Unit/Feature test PHP writes found generated view stubs and transport router fixtures under `sys_get_temp_dir`, generated PDFs/uploads under storage/temp, and a synthetic public MP4. No test was found rewriting tracked executable application/configuration PHP. Those dynamic locations are excluded. Tests that need transient tracked-source rewrites must not be added under this runtime without moving the fixture to an excluded location or explicitly excluding its target. Final digests alone cannot detect transient rewrite-and-restore behavior; this audit and same-timestamp canary are also required.

Measured diagnosis (not new-head acceptance): 150 empty Laravel application lifecycles grew approximately 15MiB without opcode caching, despite normal teardown and cycle/freelist collection; class/file counts and static-array sizes stayed stable. A pure repeated closure-file require retained about 250 bytes per compilation. Official PHP bug #76982 documents this residual compilation retention. With CLI opcode caching the same 150 lifecycle probe used a 20MiB heap peak and no progressive growth. An immutable 6,452-test comparison used 179.5MiB PHP heap plus about 128MiB opcode cache, versus 989.5MiB heap without it. That run had one unrelated reconciliation fixture error, so it is NOT a passing full-suite result. The refreshed persisted-fixture guard and complete integrated suite must be verified on a fresh exact commit before acceptance.

No heap-limit increase, test suppression, migration-loader replacement, production cache configuration, real-provider request or fiscal submission is part of this change.
