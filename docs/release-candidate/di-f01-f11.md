The DI UI/API surface now labels canonical fiscal outcomes, exposes a
reason-required portal-confirm/reject flow, exposes a reason-required
super-admin correction flow, and explains that pending verification disables
replay/edit/delete. The DI push API returns canonical state/environment/
provenance and explicitly returns `simulated` or `pending_verification`
outcomes rather than implying fiscal acceptance.

The current reservation contract has one owner: `DiFiscalSubmissionState`.
It freezes the authorized endpoint environment, creates the canonical fiscal
claim, and clears that claim on a demo outcome. `FbrService` consumes that
claim rather than creating a second one. Bulk cursor advancement now commits
an invoice outbox row in the same transaction; a redelivery flushes undispatched
rows, so a worker crash cannot silently lose the advanced range.

`FbrService` pins payload construction, bearer-token resolution and post URL
selection to `fiscal_submission_environment` from that locked claim; it does
not reload mutable company endpoint configuration. A duplicate in-flight bulk
delivery records no terminal result, so only the claim owner may settle the
batch. Privileged reference correction permits only pending verification or an
existing locked record and commits reference evidence, override audit, ledger,
and fiscal state together.

   regression `test_post_acceptance_redelivery_recovers_same_batch_success_not_skip`
