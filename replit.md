# TaxNest - Heavy Enterprise Product

## Overview
Multi-company SaaS for tax + invoice management in Pakistan (FBR/PRA compliant): smart invoicing (DI), two POS products (PRA POS "NestPOS" + FBR POS), SaaS admin layer, PDF generation, enterprise analytics, immutable audit logs. Laravel 12 / PHP 8.4, Breeze auth, Tailwind + Alpine.js + Chart.js. MySQL in production (owner's cPanel), MySQL staging in Replit dev.

### PRA reporting & billing invariants
- **Reporting-OFF Finals Invariant (PRA & FBR)**: finals with reporting OFF = regulator mode + NULL status (`'pra'`+NULL / `'fbr'`+NULL) — NEVER `'local'` (local = deliberate provisionals only). Three-branch on every write path: provisional→local/'local'; reporting-ON final→mode/'pending'; reporting-OFF final→mode/NULL (no submission; FBR-off also skips the Rs 1 fee).
- **PRA serial split**: `POS-YYYY-NNNNN` fiscal serials ONLY for bills actually reported to PRA (reporting-ON finals + promotes going to 'pending'). Provisionals AND reporting-OFF finals draw L-series; a reporting-OFF finalize/promote KEEPS its L number. Applies on all 4 write paths (storeInvoice, restaurant payOrder, apiPromoteProvisional, promoteLocalToPosSerial). Draft-resume + edit paths re-resolve the serial if the reporting toggle changed (L→POS when going to PRA; PRA never receives an L-NNN USIN; POS-serial bills never renumber downward). BOTH serial generators (POS + L, PosController + Restaurant copies) order by NUMERIC serial via DbCompat cast, never id.
- **Per-cashier PRA Reporting toggle**: `users.pra_reporting_enabled` (nullable; NULL = inherit `companies.pra_reporting_enabled`) — each POS team account flips ONLY its own switch via togglePra. Acting-user decision points read `User::praReportingEnabled($company)`; user-less contexts (offline sync job, PraIntegrationService::isEnabled, NTN-clearing guard) use `Company::praReportingActive()` (company flag OR any user ON). saas-admin company view intentionally shows the company-level flag.
- **Tax rates**: global defaults in `pos_tax_rules` (cash 16%, card/digital 8%); per-company overrides in `companies.pos_tax_rate_cash/card` (NULL = global). ALL reads via `PosTaxRule::getRateForMethod()` / `effectiveRules()` — never query the table directly. Receipts/payloads read the stored `pos_transactions.tax_rate` snapshot. Tax Reports rate-filter dropdown is DYNAMIC (never hardcode): distinct item-level rates in the CURRENT tab's data + configured effective rates, per-tab so PRA/Local sets stay isolated.
- **Rounding**: bill total = whole rupee on ALL write paths (backend `round()` matches frontend `Math.round()`); lines stay 2dp. (FBR POS & DI keep decimals.)
- **PRA Connection Mode**: `companies.pra_connection_mode` 'cloud' | 'fiscal_device'. New PRA registrations hit Code 112 on cloud PostData — must use PRAL's local IMS Fiscal Device service (`localhost:8524/api/IMSFiscal/GetInvoiceNumberByModel`, single-object payload) via the Desktop Sync Agent on the shop PC. fiscal_device mode: server never direct-submits (bills queue 'pending'); selecting it force-enables the agent + auto-generates API key.
- **Packages (annual-only)**: Starter 9,999 (1 team account, 500 bills/mo), Business 14,999 (5 / 2,000), Pro 24,999 (10 / 3,000, 2 branches, restaurant), Unlimited 39,999. Enforced via `PlanLimitService::canCreatePosBill()` (monthly FINAL-bill quota: status='completed' + invoice_mode NULL-or-≠'local', calendar month, archived rows count; trial cap separate; `invoice_limit_override` = bills/month, -1 unlimited) and `canAddPosUser()` (active pos_admin+pos_cashier vs `user_limit`; viewer portal roles exempt). Gated paths: storeInvoice finals (provisionals FREE until promoted), apiPromoteProvisional PRA branch (local-final branch exempt), retryPra ONLY when pra_status='local' (failed/offline retries not re-charged), restaurant payOrder, storeCashier + toggleCashier reactivation.
- **Roles**: `pos_manager` = full admin-equivalent (in `User::isPosAdmin()`); counts against `user_limit` like cashiers. `pos_kitchen` + `pos_waiter` registered (limit-EXEMPT, confined). Team page role selector: Manager/Cashier.
- **Standalone POS Edition RETIRED**: `standalone` plans deleted; all companies forced `pos_integration_mode='pra'`; registration edition picker removed; `PosAuthController` forces 'pra'. Null-safe dead-gated reads (`?? 'pra'`) intentionally left. Do NOT re-add standalone surfaces.

### Local billing & reports
- **Day-close policy (REVERSES old "day-close only archives" rule)**: EVERY day-close (manual + midnight auto) washes that day's local bills per STANDING company policy (Customize POS → Local Billing, admin-only POST /pos/settings/local-billing): provisionals (local+local triple) and reporting-OFF finals (completed + pra/NULL mode + NULL status + no fiscal) each get 'save' (archive) or 'delete' (permanent; items+payments too).
